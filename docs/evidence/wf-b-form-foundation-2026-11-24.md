## 3. 各项修复

### 3.1 TD-WF-006 错误提示显示英文原文

- **改前**：各控制台把 `error.message`（接口返回的英文）原样写进错误位。
- **改后**：新增 `apps/web/src/shared/api-error-message.ts`，两个导出。`apiErrorMessage(message)` 把常见接口消息转成中文；`failureMessage(error, fallback)` 是各控制台写状态之前的那一步（`Error` 取消息并转中文，其它值用兜底文案，与原来的 `error instanceof Error ? error.message : fallback` 同口径）。
- **覆盖**：整句表 12 条（冒烟里的四类都在内，幂等键的四种写法归一）+ 9 个带字段名的句式（`X is required`、`X must be …`、`X exceeds N characters`、`Unsupported fields: …`、`… version is stale|conflict`）。字段名与数值原样带进中文文案。
- **回退**：认不出的一律原样返回，逐字节不变（连首尾空白都不去）。已是中文的消息不动。句式都是整句匹配，多一个词不算命中（例如 `Employee version is stale, outside the granted data scope, …` 不会被改写成「已被修改」）。
- **接入**：线索、客户、报价、询价、供应商、采购订单、收货、物料、BOM、工艺路线、成本模型、销售政策、技术需求、商机、技术方案共 15 个文件的 `fail()` / `messageOf` / 内联赋值。跳过 `credit-console.tsx` 与 `production-order-*`。
- **没做的**：接口的信封是 `{ error: { code, message, correlationId } }`，前端 `RequestError` 只带 `message` 与状态码，所以映射只能按文案做。WF-A 新增的 4xx 文案（TD-WF-013 等）不在表里，会显示原文，合并时需要补表。

### 3.2 `FormSection` 的 `error` 属性

可选属性，渲染在既有的 `role="alert"` 提示区（提交按钮正上方）。表单自己的校验提示优先于外部错误。没有调用方时行为不变。

### 3.3 四个表单把 Promise 交还 `FormSection`（TD-WF-004 的调用侧）

主协调的 `d10a353` 靠 `onSubmit` 返回的 Promise 判断提交是否在途。四个表单写成 `{ void state.runX(values); }`，把 Promise 丢掉了：客户抽屉的「保存联系人」「保存活动」，报价抽屉的「确认批准」「确认签发」。这四个表单上提交期间按钮不置灰、重入也不拦，双击仍发两次请求；批准与签发是不可逆动作。

改为直接返回 Promise。第五处同形状的是信用决定的审批表单，在 `credit-console.tsx` 里，归主协调，本批不动。

### 3.4 TD-WF-005 新建抽屉里服务端拒绝后零提示

原则（主协调认可）：表单自己发起的提交失败，原因显示在该表单的提示区；抽屉顶部的错误位只留给不经表单的动作。同一条错误只显示一处。

- 29 处表单传入 `error`：15 个控制台的新建表单，加上详情抽屉里的行内表单（变更状态、改派、添加联系人 / 活动、报价修订 / 批准 / 签发、物料准入审核、合同文档、成本因子、政策版本、技术需求审批 / 修订）。
- 8 个详情抽屉的顶部错误位加了让位条件（行内表单打开时不显示）。非表单动作（认领、关闭询价、重算、提交评审等）仍用它。
- 报价、物料、BOM、工艺路线四个**新建**抽屉原本把错误渲染在抽屉顶部，这四个位置撤掉。
- 商机与技术方案没有提交错误状态，创建失败写进 `loadError`：商机在管道视图下整个看板被一条错误替换，而创建抽屉还开着挡在前面；技术方案的错误显示在被抽屉遮住的表格错误面里。各加一个表单错误状态（`createError`、`formError`）。
- 打开与关闭表单时清空：既有控制台原本就清空；商机、技术方案是新增的清空。

逐控制台的落点见 §4。

### 3.5 TD-WF-012 错误提示不可见

- **改前**：提示出现时不滚动、不聚焦。
- **改后**：一次提交留下了提示（校验失败、未勾选确认、或外部错误）时，把提示滚进可视区并把键盘焦点移过去。提示区 `tabIndex=-1`：可程序聚焦，不进入 Tab 序列，抽屉的 Tab 环绕不变。
- **触发条件是「这次提交留下了提示」而不是「文案变了」**：用户可能把焦点移回表单顶部再按回车，提示一字不差但仍在视口外。
- 滚动用 `block: 'nearest'`：已完全可见时不动，否则做最小滚动，相对所有可滚动祖先（抽屉体也算）。
- 提交通过时不滚动、不抢焦点。

### 3.6 TD-WF-009 必填下拉的浏览器语言提示

- **改前**：必填下拉带原生 `required`，默认空选，提交被浏览器拦下并弹出随浏览器语言的提示，表单的 `submit` 事件不触发。
- **改后**：必填下拉不带原生 `required`（保留 `aria-required` 与「必填」标记），由表单自己的校验给出「请选择{label}」，字段标 `aria-invalid`，提示按 §3.5 滚动并聚焦。
- 其它类型的必填字段不动，仍带原生 `required`。后果见 §7 的 WFB-3。
