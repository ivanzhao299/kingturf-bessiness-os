## 生产执行闭环

系统已形成从计划建议到车间执行和成品卷入库的受控链路：

1. 工单固定已发布成品版本、工艺版本及全部标准工序快照；
2. 工单通过不可变事件台账执行 `DRAFT → RELEASED → IN_PROGRESS → COMPLETED → CLOSED`；
3. 领料和退料必须引用批次库位，并与同事务库存移动逐字段一致；
4. 领料只能使用已放行且属于已发布 BOM 的物料，库存移动不能造成负结存；
5. 工序报工固定良品、废品、人工、设备、操作人和起止时间，并以业务唯一键防重；
6. 数据库按工单加事务级并发锁，累计良品不能超过计划数量；
7. 完工要求每道工序达到计划良品量，关闭要求成品序列化数量达到计划数量；
8. 成品卷号、待检批次和正向库存收货在同一事务生成并相互校验。

## 完整性与失败路径

- PostgreSQL 集成场景验证领料、退料、报工、成品卷收货、完工和关闭，并拒绝累计超量报工；
- 204 反向测试确认工单、状态事件、物料事务、工序报工和成品卷均不可修改；
- 数据库检查成品卷与工单、末工序报工、成品物料、批次及库存收货完全一致；
- 重复种子不会重复创建工单、物料事务、报工或卷号。
