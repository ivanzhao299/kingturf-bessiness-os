## 2. 行为对账

- A：`GET /api/v1/supplier-quotes` 无参加载与旧轨走同一条 SQL 和 `list('quotes')`。详情补该报价对应询价行。筛选以业务日期为界，有效包含到期当天，七天内到期包含仍有效且最迟第七天到期。排序变化时从首个键集窗口加载。比较区在客户端按同一询价行和不同供应商取已有报价全量，不新增对比接口。
- A：登记使用原 POST 写命令。报价、日期、单价、MOQ 与两级选择产生的 UUID 的 JSON 键和值逐字节对账，`receivedAt` 取确认后提交时刻。旧版会列出所有可读供应商，因此选项集沿用旧版。暂停或停用供应商仍由既有服务端资格守卫拒绝。
- B：`GET /api/v1/inventory-balances` 无参走原 `list('inventory')` SQL，保持同一批次 × 库位粒度和 movements。详情只读补来源。库存汇总按质量状态去重批次，待检为 `QUARANTINE`，可用为 `RELEASED`，拒收隔离为 `REJECTED`。概览原「待检库存」数量保留，链接打开 `QUARANTINE` 筛选。
- B：库存移动 Fastify 入口复用原校验、命令与 DTO。负库存只映射 PostgreSQL `P0001` 的 `inventory movement cannot create negative lot balance` 为中文 409。白名单外异常保持原处理。新建库位沿用 legacy POST，库存页在有既有库位时也展示入口。
- B：旧表单的 `WORK-ORDER` 取值仍为默认。服务端校验 `sourceId` 是 UUID，所以下拉显示未完工工单号，载荷使用所选工单 UUID。收货明细、生产入库及已有手工来源从该批次库位的既有移动流水提取其原类型与 UUID。
- 路由：报价需 `procurement:read`，库存需 `inventory:read`，写动作分别按 `procurement:manage` 和 `inventory:move` 渲染。两块台账已自概览退役。API 无新增写命令，无数据库迁移。
