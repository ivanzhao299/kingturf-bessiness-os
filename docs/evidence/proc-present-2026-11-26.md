## 4. B · TD-UI-012 询价矩阵行项列首行只剩「行 1 ·」

### 4.1 根因与任务书的猜测不同

任务书猜测是「可选 token 为空被过滤、分隔符留下」。实测不是：`lineText` 没有任何过滤，四个语义单元都在。真正原因是不折行 token 之间的折行：

- 三家供应商时行项列宽 166px，内容宽 150px；
- 「行 1 ·」宽 34.14px；紧跟的 SKU token「RM-KT-YARN-12000 ·」宽 131.48px；两者加中间空格约 170px，放不进同一行；
- SKU 整个被挤到第二行，首行只剩「行 1 ·」，占列宽的 23%。

### 4.2 为什么没有采用「行号并入下一个 token」

在页面上做了对照实验：把矩阵复制一份，把行号并入 SKU token，插在原矩阵旁边（同一滚动容器、同一套样式）量宽，量完删除。

| 量测                     | 读数                             |
| ------------------------ | -------------------------------- |
| 并入后的 token 宽        | 169.83px                         |
| 行项列宽                 | 166px → 185.83px                 |
| 整张表宽                 | 712px → 731.83px（对比区 712px） |
| 内层滚动容器 scrollWidth | 712 → 732，出现约 20px 横向滚动  |

列宽没有余量：行项 166 + 三家各 182 = 712，正好占满。并入会违反任务书「三家不横向滚动」和「列最小宽度不变」两条，所以不采用。主协调裁定采用下面的方案。

### 4.3 改动与理由

- `rfq-console-detail.tsx`：新增 `matrixLineText`，只给矩阵首列使用，文案次序为「行号 · 数量 · SKU · 名称」。卡片的 `lineText` 不动。行号与数量都短（「行 1 · 数量 5000 ·」111.67px），同一行放得下。四个语义单元不增不减。列最小宽度、`.proc-token` 不折行规则、矩阵 testid 都没有动。
- 手机堆叠卡片：修复前的首行就是满的（占 98%），没有同样的残片，所以文案不动，折行与修复前逐行相同。
