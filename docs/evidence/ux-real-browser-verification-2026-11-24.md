# UX 波次真浏览器验收证据（2026-11-24）

> 授权链：项目所有者第 4-7 次人裁 + 主协调全权。
> 性质：对治理 / 商机 / 客户 / 供应链 / 生产（物料、BOM）五域 UX 波次做一次真实浏览器验收，先于部署。
> 执行：UX-VERIFY 会话完成环境搭建与 e2e 首轮根因分析后停在权限审批（`needs_attention`），走查、修复与复验由主协调接管完成。

## 1. 为什么做

五个域的 UX 会话里，治理、商机、客户三个报告「本机浏览器不可用」，改动从未在真实浏览器里渲染过。此前多轮出现「报告完成 → 部署 → 人工验收发现样式丢失 / 抽屉位置错误 / 页面空白」。供应链会话用 Docker 官方 Playwright 镜像证明本机可以跑真浏览器，并且它留下的截图已经暴露出单测看不出的缺陷。本次把这件事做成全站、可复现的一遍。

## 2. 环境

| 项       | 取值                                                                                      |
| -------- | ----------------------------------------------------------------------------------------- |
| 浏览器   | Docker 镜像 `mcr.microsoft.com/playwright:v1.62.1-noble`，自带 Chromium，无头             |
| 数据库   | 专用库 `kingturf_test_uxverify`（一次性），经 `scripts/seed_p1_demo.mjs` 灌入 P1 演示数据 |
| 账号     | 合成全权限账号（193 项能力），自举脚本带库名硬闸，不是项目所有者口令                      |
| 被测服务 | 独立 worktree 的构建产物（`vite preview`）+ 同一 worktree 源码起的 API                    |
| 视口     | 桌面 1440×900；移动 390×844（设备像素比 2）                                               |

## 3. 方法

对全部 36 个路由（`AppRoute` 全集）在两种视口下各走一遍，每个路由记录：

1. 控制台报错与未捕获异常（`console.error`、`pageerror`）；
2. 状态码 ≥400 的接口响应（方法、路径、状态码）；
3. 整页截图；
4. 基于真实 DOM 量测的布局检查：表格宽于裁剪祖先且不可滚动、中日韩文字被压成每行一两个字、按钮仍是浏览器默认外观、标题或表头被截断、文字被裁切、页面横向溢出；
5. 行级「查看」：抽屉是否以固定定位浮层出现、打开时焦点是否进入对话框、连按 4 次 Tab 焦点是否仍在对话框内、Esc 是否关闭、关闭后焦点是否回到触发按钮；抽屉内重复第 4 项。

另有两项补充取证：

- **加性只读 SQL 冒烟**：把供应链、客户、生产三域的加性读方法（含筛选与游标变体）在真库上逐个直接调用；
- **e2e P1**：`tests/e2e/p1-demo.spec.ts` 11 例，用合成账号。

前两种环境下的失败不是产品问题。对失败用例的 trace 做分段计时，卡住的那个请求是 `GET /api/v1/permissions?limit=100&cursor=…`：连接建立 14711 毫秒，等待服务端响应 42 毫秒。服务端 42 毫秒就答完了，时间全花在 TCP 建连上。首屏一次性发起约 70 个新连接（预览代理对每个响应都回 `Connection: close`），经 Docker 的地址转换中转时个别握手包被丢，要等三次重传（约 15 秒）才成功。把三个进程放进同一个网络命名空间后问题消失。

## 6. 这次验证没有覆盖什么

- **只走了读路径。** 新建、发布、状态流转等写操作没有在浏览器里点过，它们目前只有单元、契约与真库测试覆盖。台账 TD-TEST-024。
- **只用了一个全权限账号。** 按权限隐藏或裁剪的呈现形态（有限角色的菜单、按钮、字段）没有在浏览器里看过。
- **只有 Chromium，只有两种宽度。** 没有 Firefox、WebKit，没有平板宽度和更窄的手机。
- **布局检查是启发式的。** 能稳定抓到表格裁切、一字一行、默认按钮、标题截断、页面溢出这几类；重叠、对齐、配色、间距这类观感问题不在这个能力内，要靠人看截图。
- **e2e 只在合成账号与演示数据上跑。**

## 7. 过程中确认的两件事

**独立会话停在权限审批上。** UX-VERIFY 与 PROC-2 两个会话的状态是 `needs_attention`，各有命令在等人批准（`approval=requested`），并非故障。今天新建的会话权限模式是逐条审批。审批只能由项目所有者在界面上完成。

**本地 e2e 的可靠跑法。** 浏览器、预览代理、API 三个进程放进同一个 Playwright 容器，只有数据库连接穿过 Docker。这套环境下仓库原配置可以稳定跑出 11 / 11。配方尚未入库，脚本暂存于 `/tmp/coord-release/harness/`，登记为 TD-TEST-023。
