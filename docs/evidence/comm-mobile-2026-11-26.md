## 4. 根因

佣金卡片是一个两列网格，提示与台账都被自动排进了这两列并排放在同一行。

- `apps/web/src/style.css:2802-2810`：`.qtc-card { display: grid; grid-template-columns: minmax(0, 1fr) auto; }`。这两列是给「金额 | 状态徽章」这一行用的。
- `apps/web/src/style.css:2811-2819`：跨两列的清单（`.eyebrow`、`.muted`、`.qtc-metrics`、`.version-pin`、`.input-hash`、`.qtc-actions`、`> .primary`）。清单里没有 `.next-action-note`，也没有 `.commission-ledger`。
- `apps/web/src/commercial/commission-ledger.ts:43` 的 `<p class="next-action-note">` 与 `:45` 的 `<ol class="commission-ledger">` 于是被自动放置：提示落在第一列，台账落在紧跟的 `auto` 列，两者同行。经 CDP 取匹配规则，提示上没有任何设置布局属性的规则（`grid-column` 为默认的 `auto`）。
- 轨道分配时 `auto` 列先按台账的最大内容宽生长，`1fr` 列只能拿剩余空间。台账最长一行不折行时宽 523.609px（文字 483.61px + 列表缩进 40px），一旦它不小于卡片内容宽减列间距，第一列就是 0。

## 5. 改动与理由

`apps/web/src/style.css:2820-2836` 新增两条规则，其余未动：

```css
@media (max-width: 1023px) {
  .qtc-card .next-action-note,
  .qtc-card .commission-ledger {
    grid-column: 1 / -1;
  }
}
@media (min-width: 1024px) {
  .qtc-card.commission-card {
    grid-template-columns: minmax(16%, 1fr) auto;
  }
}
```

- **非桌面档（≤1023px）两者各占整行。** 断点与应用壳的桌面阈值一致：`apps/web/src/shared/shell-presentation.ts:40` 把小于 1024 的宽度归为 `mobile` / `tablet`，样式表 `:3532` 既有的平板块也是 `max-width: 1023px`。基线扫描显示 320–900px 提示的内容宽都是 0，960px 是 5 行，只修到 639px 会把平板档原样留下。
- **为什么连台账一起跨列。** 台账正是落进 `auto` 列、把第一列挤成 0 的那个兄弟。只让提示跨列的话，台账会留在左列，比其它行窄一个徽章宽（390 下 232px 对 290px），右边空出一列。
- **桌面档（≥1024px）保留并排，只给第一列 16% 的下限。** 这一段是主协调看过实验后要求并入的，目的在于消除「台账行足够长时桌面同样被挤成 0」的隐患。没有动 `.qtc-card` 的共享轨道定义，规则只命中佣金卡片。
- **16% 的来历。** 不改变任何一档演示布局时，最窄桌面档（1024）第一列的现状是 105.27px，占卡片内容宽 640.87px 的 16.4%；16% 是略低于它的整数取值，余量 2.73px。6.5rem（104px）同样能通过，但在比 1024 宽的各档下限都更小，所以取百分比。
