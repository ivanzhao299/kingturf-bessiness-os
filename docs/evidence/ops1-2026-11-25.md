## 行为变更登记

- **ops1-1** 创建检验计划的旧表单没有检验说明输入，始终发送 `instructions: ''`。在 `4522430` 的原校验器上，仓库隔离 HTTP 夹具以该 JSON 得到 HTTP 400 `instructions is required`。同一真库的现有仓储成功创建并发布空说明计划。既有 `instructions text NOT NULL` 允许空字符串。修复限于创建检验计划解析器接受这一字面值，保留其他说明值和所有其他字段的原校验。复现日志 `/tmp/ops1-logs/ops1-original-http-400.log`。
- **ops1-2** 质检和投诉桥轨将列出的 PostgreSQL `P0001` 业务拒绝映射为 409 中文提示。未列出的异常沿用现有桥轨的 500 处理。质检和投诉的低层写命令沿用原分派。
- **ops1-3** 投诉旧表单使用裸随机 UUID 作为幂等键，登记真实 HTTP 返回 400。按协调裁定，稳定编号验证覆盖的投诉、NCR、CAPA 命令使用 `CMP-` 加大写随机 UUID。批量分派的 `batchKey` 单独实测，同规则。其他字段与全局请求 ID 生成器沿用原行为。
- **ops1-4** 旧表单允许空检验数值上下限、结果备注及临时遏制说明，但对应旧端点对空字符串校验会拒绝，待协调登记。
- **ops1-5** 旧签收表单发送 `POD-` 加小写发运 UUID，原端点校验返回 HTTP 400。修复仅匹配签收 URL 的同一 UUID，原键保存至事件台账。异号 UUID、非法普通编号和同一 POD 键用于运输流转分别返回 400，普通合法编号用于运输流转返回 201。真 HTTP 复现 `/tmp/ops1-logs/ops-pod-http-400.log`，修复验证 `/tmp/ops1-logs/ops-api-directed-final.log`。
- **ops1-6** 发货桥轨同样按白名单将现有数据库守卫拒绝转为中文 409。

## 读取与写入对账

| 台账     | 默认响应与筛选                                                                | 详情与汇总                                                                           |
| -------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| 检验计划 | 原 `items`，加性筛选支持全权角色按状态和关键词查询，键集为计划编码、版本与 ID | 特性与验收规则，发布沿用原 POST                                                      |
| 检验单   | 原 `items`，加性键集为开立时间与 ID                                           | 计划、批次、结果和处置，分别统计全授权数据集中的 OPEN、SAMPLED、COMPLETED            |
| 投诉     | 原 `items`、`nextCursor`，沿用服务端状态、查询和关闭期限与 ID 键集            | SLA 关闭倒计时、时间线和既有 NCR／CAPA 工作流                                        |
| 批次追溯 | 原 `items`，加性键集为创建时间与批次 ID                                       | 成品卷、工单领退料、库存移动和质量事件的可折叠分组，全授权数据集中的 QUARANTINE 计数 |
| 发货放行 | 原 `items`，加性键集为创建时间与申请 ID                                       | 九类冻结门禁、放行审批、发运和签收事件，统计全部申请、待例外审批、已放行及已签收票数 |

表头使用共享 DataTable 对当前已加载行排序。关键词、状态筛选和继续加载走服务端。汇总独立于当前页和筛选值。机械回验三条质检和一条发货默认 SQL 分别为 697、1,275、1,593、1,242 字节，与基线逐字节一致。见 `/tmp/ops1-logs/default-sql-parity.log`。读取受原能力与数据范围约束，加性接口沿用字段裁剪。质检创建沿用原 `publish: true`。独立草稿发布沿用 `POST …/publish` 与空对象载荷。签收沿用原 `POD-…` 的请求字节，其余投诉类写入的已裁差异见 ops1-3。
