# JTF-P0-E10 — Generic workflow

Migration 0005 defines tenant-owned immutable published specifications, pinned instances, versioned tasks, immutable decisions, and transition history. The domain validator requires distinct known states, initial/terminal states, legal transitions, ordered steps, eligible actors/roles, foundation quorum of exactly one, and requester-separation flags. Unsupported multi-vote quorum fails closed rather than silently weakening approval. The schema and vocabulary intentionally contain no sales, credit, commission, shipment, or manufacturing policy.

Secured APIs create later drafts, publish, idempotently start instances against the exact version, expose only actor/role-eligible tasks, and decide with optimistic task versions. A decision validates the generic transition, enforces configured requester separation in PostgreSQL, updates state, appends immutable history, and audits in one transaction. Advisory locks make concurrent retries return the original start or decision. Migration 0006 adds assignment invariants, tenant/separation guards, queue indexes, and published-delete protection. The PostgreSQL scenario covers assignment, separation, idempotency, completion, immutable history, and tenant boundaries.
