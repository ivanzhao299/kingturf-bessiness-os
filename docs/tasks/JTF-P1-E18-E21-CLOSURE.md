# JTF-P1-E18–E21：销售到回款经营闭环

状态：PLANNED（KT-L08～KT-L11）

## 目标

在现有 E01–E17 交易链上补齐佣金、Order 360、风险和管理驾驶舱，使管理人员能够从指标或异常下钻到不可变业务证据，并把异常转成可跟踪任务。

## E18 佣金引擎

- 版本化佣金政策及适用范围。
- 状态：`ACCRUED -> FROZEN -> RELEASED -> PAID`，支持 `CLAWED_BACK` 与 `CANCELLED`。
- 金额由符合条件的收入、利润、回款、质量和风险因素推导，不允许直接覆盖台账余额。
- 政策版本、输入快照、计算轨迹、审批和会计期间永久保留。

## E19 Order 360

- 以 Business Order ID 聚合商机、CTR、方案、成本、政策、报价、信用、合同、签署、订单、应收、收款和佣金。
- 所有模块独立执行读取权限、字段权限和 DataScope；聚合层不得扩大可见范围。
- 同时提供摘要、差异、异常和按发生时间排序的证据时间线。

## E20 风险引擎 v1

- 初始规则覆盖信用到期、额度占用、逾期、低毛利、合同/签署缺口和订单释放条件。
- 每次评价固定规则版本、规范输入、结论、原因、建议动作和有效期。
- 高风险结论生成工作流任务；关闭必须附责任人、理由与证据。

## E21 管理驾驶舱

- 指标：销售预测、签单、收入、毛利、现金、应收、逾期、订单交付和风险。
- 每个指标定义时间口径、币种、数据来源、刷新时间和权限边界。
- 异常优先排序，可按组织、负责人、客户和业务单据下钻。
- 仪表盘只读取可复算的服务端聚合，不在浏览器拼接财务口径。

## 验收场景

1. 全款正常订单：签发、签署、订单、应收、收款、核销、佣金释放全部可追溯。
2. 逾期订单：风险引擎标记、佣金冻结、驾驶舱告警并生成责任任务。
3. 低毛利例外：保留成本/政策/报价版本与审批证据，未批准不得继续。
4. 权限隔离：不同区域用户不能通过 360 或驾驶舱聚合看到越权客户与财务字段。
