## 1. 项目概况

**一句话定位**：KingTurf 业务操作系统——面向草坪行业外贸业务的 ERP（CRM→报价→订单→生产→发货→财务全链路），生产站点 `https://erp.kingturf.cn`。

- **技术栈**：pnpm 10.33.4 workspace monorepo（Node 24 / TypeScript 5.9.3，`"type": "module"`，零前端框架、零后端框架）
- **构建方式**：`pnpm -r build`（apps/api 走 tsc 出 dist；apps/web 走 vite build + 启动预算断言 `scripts/check-startup-budget.mjs`）
- **运行方式**：本地 `pnpm dev`（web:5173 / api:3000，dev 直跑源码 `node --watch --experimental-strip-types`）；本地 PG 经 `infra/docker/compose.yaml`
- **部署方式**：手动 `workflow_dispatch`（指定 commit_sha）→ verify 全量门禁 → SSH 到新加坡主机 → rsync + nginx 配置校验（sha256 比对）→ `docker compose -f infra/docker/compose.production.yaml up -d --build` → 健康探针（version 必须等于 SHA）。**无 tag、无 GitHub Release、无自动发布。**
- **顶层模块与入口点**：

| 模块                | 职责                                                                               | 入口                                                                                     |
| ------------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------- |
| `apps/api`          | Node 原生 `node:http` API（组织/员工/认证/授权 + 20 个业务域仓储与路由）           | `src/server.ts`（组合根）→ `src/app.ts`（路由总装）                                      |
| `apps/web`          | Vite 构建的 vanilla TS SPA（原生 DOM，无框架）                                     | `index.html` → `src/main.ts` → `entry.ts`（登录流）→ 懒加载 `bootstrap.ts`（业务工作台） |
| `packages/types`    | 共享 DTO/枚举/ErrorEnvelope（约 537 行，纯类型）                                   | `src/index.ts`                                                                           |
| `packages/domain`   | 框架无关领域规则（DomainError/canonicalize/信贷评估/权限断言，约 1,031 行，无 IO） | `src/index.ts`                                                                           |
| `packages/config`   | `parseEnvironment` 环境解析 + 共享 tsconfig 模板                                   | `src/index.ts`                                                                           |
| `packages/database` | pg 8.22.0 封装 + 迁移 CLI + **70 个有序 SQL 迁移**                                 | `src/index.ts` / `src/cli.ts`                                                            |
| `tests/e2e`         | 12 个 Playwright 规格（chrome 单 worker 串行）                                     | `playwright.config.ts`                                                                   |

- **当前测试与 CI 现状**：53 个测试文件 / 约 17,265 行 / 约 350 用例（vitest 单测+mock 路由级、13 个 PG 集成、12 个 Playwright e2e）；CI = `pnpm ci:local` 完整有序链（format→capabilities→db guard→migrate→status→lint→typecheck→test→build→audit），PR/push main 触发，本地一条命令可复现。**无 git hooks、无覆盖率、无 commitlint**（详见台账 TD-GATE/TD-TEST 组）。
- **既有工程亮点（改造时必须保持）**：包级依赖为干净 DAG 无循环；tsconfig/eslint 为超严格配置（strictTypeChecked + noUncheckedIndexedAccess 等）；SQL 全参数化；opaque token + scrypt；统一 http 封装（15s 超时 + correlation-id）；启动预算量化门禁；前端能力清单校验；文档纪律好——10 个 ADR，`docs/evidence/` 29 个验收证据文件（复核：`ls docs/evidence | wc -l`），源码 TODO/FIXME 0 处（复核：`grep -rnE 'TODO|FIXME' apps packages --include='*.ts' | grep -v '\.test\.'`；docs 文档内另有 2 处 TODO 字样，属文档内容非代码债务）。

### 3.1 架构现状（依赖图）

方法：包级 = 8 个 `package.json` 的 workspace 依赖 + 全量 import grep 交叉核对；应用级 = `grep -n 'import type'`（app.ts:20-43 验证 type-only）+ api/src 与 web/src 的 import 链逐文件核对。

**包级（干净 DAG，无循环依赖——亮点）**：

```text
apps/api ──→ packages/{config, database, domain, types}
packages/database → pg（唯一外部运行时依赖）
packages/domain → packages/types
packages/{types, ui, config, testing} → 零依赖
```

- `apps/api/src/app.ts` 对 20 个 repository 全部 **type-only import**（依赖倒置正确）；`server.ts` 是唯一组合根。
- web 侧 import 链无反向引用：`main → entry → {login-flow, workspace-loader → bootstrap → {dom, brand, http, session, …}}`。

**应用内部（层级塌陷——两大问题源）**：

- **后端**：Repo 之上没有 Service 层。`buildApp`（app.ts:383-6824，≈6,442 行）以 230 个顺序 if 分支吞掉"校验+授权+编排+DTO 组装"全部职责（TD-API-001）。
