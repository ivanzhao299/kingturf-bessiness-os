# ADR-0013：租户设置中心（Tenant Settings Center）

日期：2026-11-18。状态：**草案（CP4 待人工确认）**——仅文档；D5 实施与迁移 0074 不因本 ADR 自动开始。授权链：2026-11-18 项目所有者两次人裁（D5 立项需新 ADR；执行授权见[执行计划](../tasks/system-admin-optimization-plan-2026-11-18.md) §0/§2.5/§7）。

## 背景

当前无租户级统一参数存储：locale/currency 在组织列、应用配置在 env、业务策略散落于 6+ 自有版本化表（编号/规则/工作流/成本/佣金/风险等，ADR-0005 形态）。安全与体验类「单值键值参数」（如密码最小长度、登录横幅）没有归属：写进 env 会绕过租户隔离与审计，为每个键建专用版本表又重复造轮。评估报告提出 D5「统一租户配置中心」，复核修正 #8 指出空壳风险——无首批键则成空架子，故 Phase 1 必须绑定试点键（见决策 6）。

## 决策

建立**租户设置中心**，遵循 ADR-0005「稳定身份 + 追加版本」形态：

1. **两张表（迁移 0074，纯加性）**：
   - `tenant_settings`：稳定身份行，`tenant uuid + key text UNIQUE`（每个键每租户至多一行），持当前生效版本指针；
   - `tenant_setting_versions`：追加版本行，`value jsonb`、`status DRAFT|PUBLISHED`、版本号、操作者与时间；**发布单向**（DRAFT→PUBLISHED 一次性动作，不可回退状态）；**已发布行禁改禁删**（UPDATE/DELETE 触发器异常，与 ADR-0005 平台引擎保护同款）。
2. **key 目录由代码注册（白名单）**：键名、默认值、约束由代码常量声明，未注册键的读写一律拒绝（default-deny）；**每键 JSON schema 手写校验**（类型/区间/长度），不引入 zod/ajv，维持零新运行时依赖（R6）。
3. **读取语义**：消费者只解析「当前 PUBLISHED 版本」；DRAFT 对业务读取不可见（预览走管理端点显式请求）。未设置的键回落代码默认值，不造无主数据行。
4. **API（新 capability）**：`tenant-setting:read` / `tenant-setting:manage` 纳入权限目录种子；`GET /api/v1/tenant-settings`（列表+当前值+版本指纹）、`PUT /api/v1/tenant-settings`（写 DRAFT，**幂等键必须**）、发布动作端点（DRAFT→PUBLISHED，同样幂等）。授权走既有 default-deny + 字段/DataScope 体系。
5. **审计同事务**：创建/发布/指针推进与既有 `auditTx` 同事务写入，元数据走既有 allowlist 机制；不新增外发通道。
6. **Phase 1 试点键（防空壳，均为只读消费预留）**：
   - `security.password.minLength`：integer 8–128，默认 12（供 A1 后续消费；当前密码策略读取路径不因本批改动）；
   - `security.password.historyCount`：integer 0–24，默认 0（为 §2.6 未批项 A3/A4 预留，仅存储不消费）；
   - `ux.loginNoticeText`：string ≤500 字符登录横幅。
7. **前端**：`governance/system` 子页新增「系统参数」区（键-值表单 + 发布按钮 + 版本只读历史），复用治理表单/分页组件。
8. **既有 env 与组织列不迁移**：收敛范围另批（本 ADR 只立机制与试点键，不动 locale/currency 等存量读取方）。

## 后果

- 租户级单值参数获得统一归属：租户隔离、审计、版本历史、发布护栏开箱即用；后续新键只需代码注册（白名单 + schema + 种子能力评估）。
- A1（强制首登改密）后续可把密码策略读取切至 `security.password.minLength`，避免重复造策略读取路径（计划 §1#8）；A3/A4 若获批，historyCount 已就位。
- 迁移 0074 纯加性（两新表+触发器），不改写既有行；Wave 2 随部署执行（2026-11-18 二次人裁解除独立迁移授权，保留恢复点与隔离演练）。
- 回滚边界：应用层回退后新表对旧代码无读写冲突；旧应用启动元数据校验对 unknown 迁移 fail-closed——应用回滚策略按计划 §5 于 CP6 检查点裁决；已发布设置行永远禁删，反向迁移被现有契约禁止。
- 成本：每次发布产生一行 jsonb 版本（试点键量级极小）；读取走「当前指针」单查询，不引入缓存层。

## 替代方案（已拒绝）

- **env/组织列继续承载**：无租户隔离、无审计、无版本；新键要改代码或重启——拒绝。
- **每键专用版本表**（完全复制 ADR-0005 各引擎）：单值参数无多字段结构，逐键建表纯增 schema 与查询面——拒绝。
- **单表 JSONB 全量 blob**（无版本/无发布）：丢失发布护栏与历史；误改直接影响生效值——拒绝。
- **引入 zod/ajv 做键校验**：违反零新依赖红线（ADR-0001/R6）；手写每键 schema 的校验面小且 100% 可测——拒绝。
- **DRAFT 可撤回已发布状态**：破坏「发布即冻结」的不可变决策原则（ADR-0005）；纠错=发布新版本——拒绝。

## 验收要点（D5 实施批用，见计划 §4）

迁移/触发器负例（已发布禁改禁删）；键 schema 校验负例（越界/类型/未注册键 403/404）；发布与版本追加正例；审计同事务断言；幂等键重放返回既存不可变快照；UI 行为测试；干净 HEAD 完整 ci:local 实跑 0。
