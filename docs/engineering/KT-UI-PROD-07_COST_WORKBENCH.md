# KT-UI-PROD-07 成本模型生产工作台

日期：2026-09-04

## 产品结论

成本模型属于可比较、可筛选、持续增长的业务对象，不再使用“每个模型一张卡片、在卡片内展开因子”的展示方式。生产工作台采用三层结构：

1. 摘要指标只表达模型总量和当前页异常；
2. 台账列表负责检索、比较、排序和定位；
3. 独立详情工作区负责因子维护、重新核算、报价交接和审计追溯。

## 岗位边界

| 岗位           | 默认关注内容                         | 允许动作                             |
| -------------- | ------------------------------------ | ------------------------------------ |
| 成本测算专员   | 因子完整度、取价依据、待重新核算模型 | 维护因子、执行核算、形成报价成本快照 |
| 报价编制专员   | 已核算并已冻结的成本决定             | 引用成本决定创建报价                 |
| 报价审批与签发 | 毛利、政策例外和冻结证据             | 审批或签发报价，不修改成本因子       |
| 管理与审计     | 成本结果、报价引用和变更轨迹         | 只读查看与追溯                       |

前端展示不扩大权限。所有查询、维护、核算和报价交接继续由服务器原子权限、公司数据范围和业务状态机控制。

## 页面结构

- 列表按异常优先排序，支持关键词、处理状态和成本排序。
- 每页默认 20 个模型；列表接口不返回成本因子或完整核算轨迹。
- 打开模型时按需读取因子、最近 30 次核算和最近 50 条模型变更日志。
- 详情页使用固定阅读轴和页签：成本因子、核算记录、报价引用、变更日志。
- 成本因子使用宽编辑对话框，字段按基本信息、耗用与价格、价格依据与追溯分区。
- 编辑区存在未保存修改时，关闭前必须再次确认。
- 重新核算立即显示进行状态；完成后显示综合成本及与上次结果的差额。
- 报价交接继续冻结精确的成本决定，并将有权限的报价编制人员直接带入预选成本的报价表单。

## 接口契约

### `GET /api/v1/cost-matrix-summaries`

查询参数：`page`、`pageSize`、`q`、`productFamily`、`attention`、`sort`。返回轻量模型摘要、总数和分页信息，不返回 `factors`。

### `GET /api/v1/cost-matrices/:id`

返回单个模型、完整因子、最近核算记录及模型级审计轨迹。必须具备 `cost-matrix:read` 和 `COMPANY` 数据范围。

原有 `GET /api/v1/cost-matrices` 暂时保留兼容，不再作为新版页面首屏数据源。

## 验收标准

1. 100 个模型不会在首屏下载或生成全部成本因子节点。
2. 桌面列表保持单一纵向扫描线；移动端允许台账区域横向滚动，不隐藏金额、状态和操作。
3. 成本因子编辑区桌面最大宽度 840px，移动端接近全屏。
4. 搜索输入防抖 280ms；筛选、排序和分页只刷新成本模型台账。
5. 添加、修改、核算后只刷新当前模型详情和摘要页，不重载整个商业工作台。
6. 成本因子、核算记录、报价交接和审计日志分别可见且权限一致。
7. 成本测算、只读、报价编制三个代表角色通过桌面、平板和 390px 浏览器验收。
