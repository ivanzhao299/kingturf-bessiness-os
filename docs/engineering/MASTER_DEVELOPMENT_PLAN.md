版本：1.0

## 1. 最终开发意向

建设一套适用于人造草坪制造与外贸业务的经营操作系统，使一笔真实业务能够从线索进入，经过客户、商机、技术需求、成本、报价、信用、合同、订单、计划、采购、生产、质量、仓储、交付、应收、回款、佣金和利润核算，最终形成可追溯、可审计、可预警的闭环。

最终产品不是模块集合，而是三个统一工作面：

1. 销售工作台：让销售人员用最少录入完成客户推进、报价、合同、订单和回款跟进。
2. 运营工作台：让技术、采购、计划、生产、质量、仓库、财务和法务按队列协同。
3. 管理驾驶舱：按异常、现金、利润、交付和风险排序管理，而不是只看静态报表。

## 2. 实施目的与成功标准

| 目的                | 终局验收标准                                                   |
| ------------------- | -------------------------------------------------------------- |
| 替代外部 Excel 台账 | 一笔订单从获客到 100% 回款及佣金结算无须外部台账               |
| 建立利润真实性      | 每笔完结订单具有计划成本、实际制造成本、全成本与差异解释       |
| 控制信用和交付风险  | 超额、逾期、质量未放行或合同证据不完整时系统阻止发货           |
| 建立证据链          | 关键单据、审批、签署、物流、收款及变更形成不可静默删除的时间线 |
| 提升管理响应速度    | 驾驶舱能从异常指标下钻到责任人、业务单据和建议动作             |
| 形成 AI 闭环        | AI 建议可转为任务、跟踪、升级，但高风险决定仍由授权人员批准    |

## 3. 现状审计基线

### 已具备

- P0：组织、身份、RBAC/DataScope、审计、工作流、规则、通知、附件、事件、编号和业务对象基础。
- P1 E01–E17：客户、线索、商机、CTR、技术方案、成本、销售政策、报价、信用、合同、签署、订单、应收、银行收款和核销的后端边界。
- 安全与证据：租户组合键、乐观锁、幂等命令、不可变版本、审计与事务性事件。
- 运行环境：GitHub 主仓库、CI 基础、204 隔离预览环境、持久化 PostgreSQL。

### 主要缺口

- 商业链大量操作仍依赖 JSON 输入，缺少业务字段表单、校验、状态导航和详情页。
- 缺少可演示的完整种子业务数据和端到端浏览器验收。
- P1 E18–E21（佣金、订单 360、风险、驾驶舱）尚未形成闭环。
- P2–P5 尚未实现；真实制造成本、发货控制和证据包是后续关键门槛。
- 预览环境仍采用弱口令与开发级本地附件存储，不满足生产发布条件。

## 7. 每项任务的统一完成门槛

1. 有任务规格：用户、范围、非目标、状态机、权限、审计和失败路径明确。
2. 有迁移与回滚策略；不可修改已经发布的历史迁移。
3. API 默认拒绝，DataScope 和字段权限在服务器端执行。
4. 关键命令具有幂等、乐观并发、审计和事务性事件证据。
5. 前端不再以原始 JSON 作为主要业务操作方式。
6. 单元、集成、浏览器 E2E、类型、格式、构建和安全门禁通过。
7. 在 204 预览环境完成真实场景演练并记录验收结果。
8. 文档、运行手册、已知限制和下一依赖同步更新。

## 8. 计划治理

- 每周一更新节点状态、剩余工时、风险和本周验收目标。
- 每个里程碑前执行一次架构、安全、数据完整性和产品可用性审计。
- 发现红线风险时暂停新增范围，先修复租户隔离、账务真实性、历史版本或证据完整性。
- 未完成的任务不得仅因日期到达而标记完成；必须提供代码、测试和预览验收证据。
- 新需求进入积压池，只有明确业务价值、依赖、工时和验收标准后才能进入当前节点。
