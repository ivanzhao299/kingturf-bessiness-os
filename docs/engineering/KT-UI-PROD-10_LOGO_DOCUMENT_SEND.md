# 登录标志与文档发送反馈修复

## 基线与范围

2026-09-05 从隔离工作树开始；本地选定基线、origin/main、生产 /version 与 .release-sha 均为 `22a80d1daeed2782b0a62e0fee691c13e39655cc`，三个 ERP 容器健康。正式入口仅 `https://erp.kingturf.cn`。不变更生产业务数据、客户地址、渠道密钥、DNS 或迁移恢复点，不进行真实外发。

## 根因与修复

- 原始品牌 PNG 为 188,055 字节、512px，登录仅显示约 64px，并且作为低优先级独立请求加载。保留原始品牌文件，生成 128px / 6,662 字节的透明 WebP 衍生图；通过共享 `brand.ts` 内联到登录入口，登录及业务标志不再请求原 PNG。图片本体减小约 96.5%，消除额外图片网络往返；不是承诺所有地区固定秒数。
- JS gzip 从约 3.72 KB 增至约 11.14 KB，已包含图像。登录 CSS 仍约 1.89 KB，业务资源仍延后加载。JS 构建预算从 8,000 调整到 12,000 字节，明确包含内联标志；CSS 4,000 字节预算不变。此前统计未包含原 PNG，本轮不要只比较 JS 得出性能退化结论。
- 文档发送按钮此前直接 disabled，仅 title 解释未绑定客户或未审批；点击无反馈。现在即时显示顶层可访问弹窗，区分未绑定、草稿、待审批、归档、读取渠道中、渠道未配置和读取失败；支持返回文档再重试，关闭加载弹窗会取消读取，不迟到重开。
- 审批成功后即时同步编辑权限、审核按钮和发送条件，不要求关闭重开。未保存正文不能直接提交审核。保存响应不覆盖请求期间继续输入的内容。
- 只列出 READY 渠道；同一发送表单内，同一请求内容重试复用幂等键，处理中拦截重复提交。成功反馈显示任务号和真实状态，版本栏不再把 QUEUED 标为“已发送”。角色权限与服务端审批/客户/版本检查保持不变。

## 外发能力未完成的明确边界

本轮生产只读查询 `business_document_connectors` 为 0 行，即没有已配置企业发送渠道。当前仓库只创建 `business_document_dispatches` 及 `business-document.dispatch.requested` outbox 事件，尚无实际文档外发消费者。**配置界面、入队成功不代表邮件/微信已发送或客户已收到。** 本轮修复交互和状态真实性，不宣称真正外发已经打通。

下一步需确认优先渠道（企业邮箱 / 企业微信 / WhatsApp 等），通过受控秘密配置接入对应企业账号，再实施服务端发送任务、重试与死信、提供商回执、版本/译文附件、逐用户审计和受控测试收件人验收。不得在前端存密钥，不得直接向真实客户试发。现有未绑定文档只能在草稿期经受控绑定接口更改；本轮没有扩展该接口或放松审批锁版。
