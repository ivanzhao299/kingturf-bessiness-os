# KingTurf 原子角色与 UAT 矩阵

版本：1.1 · 2026-08-24

## 设计原则

角色表达一项可审计职责，而不是菜单集合或人员级别。员工通过组合原子角色获得岗位能力；生产默认 `COMPANY` 数据范围，后续组织成熟后再把销售、区域和班组岗位收紧到 `SELF / TEAM / DEPARTMENT / REGION`。前端隐藏不构成授权，所有动作仍由服务器 RBAC、数据范围、字段权限和业务状态机共同约束。

六条强制职责分离规则：

1. 报价编制、报价审批和正式签发不可由同一原子角色完成。
2. 信用评估与信用批准不可由同一原子角色完成，系统继续禁止批准自己的信用决定。
3. 质检执行与批次放行不可由同一原子角色完成。
4. 制造成本核算与制造成本审批不可由同一原子角色完成。
5. 发货申请与发货例外审批不可由同一原子角色完成。
6. 平台/IAM 管理员不得因技术权限取得业务审批权限；系统审计员只读。

## 岗位组合建议

小规模公司允许一个员工持有多个不冲突角色，但以下组合必须禁止或书面例外审批：

- `报价编制专员 + 报价审批员/报价签发员`
- `信用评估专员 + 信用审批员`
- `合同编制专员 + 合同签署确认员`
- `收款登记员 + 回款核销会计`
- `佣金核算专员 + 佣金支付确认员`
- `需求与 MRP 计划员 + MRP 批准与释放员`
- `质量检验员 + 质量放行经理`
- `制造成本核算会计 + 制造成本审批员`
- `发货申请员 + 发货例外审批员`
- `身份与权限管理员/平台运维管理员 + 任一业务批准角色`

## UAT 分层

1. **角色目录 UAT：** 每个生产公司自动获得 47 个业务原子角色；名称、能力数量和 `COMPANY` 范围准确。超级管理员和系统管理员属于平台管理角色，不计入业务原子角色数量。
2. **身份 UAT：** 为每个角色建立一个临时单角色身份，登录后会话能力与数据库授权精确一致。
3. **允许路径 UAT：** 每个角色至少访问一个职责内真实生产接口，必须返回成功。
4. **拒绝路径 UAT：** 每个角色至少访问一个职责外接口，必须返回 403；关键职责分离额外检查能力不存在。
5. **前端 UAT：** 选择销售、财务、采购、生产、制造成本、质量、仓储、物流、审批、管理、审计和 IAM 代表角色，核对菜单、工作台、直接地址拦截、无权操作、浏览器错误和 390px 页面。
6. **清理：** 临时 UAT 身份测试后停用；保留员工、角色、授权、登录审计和 UAT 报告，不保留明文密码。

## 验收出口

- 迁移可重复、未来新公司自动配置、旧公司不丢失现有管理员权限。
- 每个角色至少一项允许和一项拒绝证据；所有关键职责分离断言通过。
- 生产管理员、现有业务数据和既有会话不受破坏。
- 全量测试、精确 SHA 部署、健康/就绪、真实浏览器 UAT 和飞书回执齐全。
