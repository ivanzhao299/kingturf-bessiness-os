# KT-UI-PROD-06 业务流程导航

## 目标

左侧导航以业务阶段为入口，每个菜单只打开一个主要任务页面。菜单可见性继续由原子权限决定，前端拆分不扩大任何数据或操作权限。

## 固化流程

| 业务主线     | 菜单顺序                                                 | 页面职责                               |
| ------------ | -------------------------------------------------------- | -------------------------------------- |
| 客户与商机   | 销售线索 → 客户管理 → 销售商机                           | 线索分配、客户档案、商机推进           |
| 技术与报价   | 技术需求 → 技术方案 → 成本核算 → 销售政策 → 销售报价     | 技术确认、方案定版、核价与报价签发     |
| 合同与订单   | 信用审查 → 合同管理 → 销售订单 → 订单全景                | 信用门禁、合同签署、订单释放与履约证据 |
| 财务与风控   | 应收账款 → 催收与法务 → 收款与核销 → 销售佣金 → 业务风险 | 债权、到账、佣金和风险闭环             |
| 供应链与生产 | 制造主数据 → 采购管理 → 物料计划 → 生产执行              | 基础数据、采购收货、供需运算与工单执行 |
| 质量与交付   | 质量检验 → 发货与签收                                    | 检验放行、发运、物流和签收证据         |

## 约束

1. `AppRoute` 是菜单、页面标题、URL 和工作台显示状态的唯一入口定义。
2. `visibleAppRoutes` 只依据原子权限开放对应菜单。
3. 每个主要工作台只绑定一个明细路由；概括工作台不再作为业务操作入口。
4. 同一页面可以保留与主任务直接相关的门禁摘要，但不得混入其他业务阶段的操作台。
5. 新增后台能力时必须同时补齐原子权限、明细路由、菜单入口和角色 UAT。

成本核算路由内的高密度模型台账、独立详情和报价交接遵循
[KT-UI-PROD-07 成本模型生产工作台](KT-UI-PROD-07_COST_WORKBENCH.md)。

## 成本到报价交接

成本模型不是报价单本身，两个环节通过不可变成本决策连接：

1. 采购专员维护采购订单、合同价和有效供应商报价；成本因子可引用这些价格，也可使用注明来源和生效日期的市场或企业基准。
2. 成本测算专员新增或维护因子，执行含税或未税核算，系统保存因子数量、解析后的价格来源和成本快照。
3. “用于报价”要求选择定稿技术方案和已发布企业成本规则，随后把该次核算冻结为 `costDecisionId`，不得把可变成本模型直接交给报价。
4. 同时具备 `quote:read` 与 `quote:create` 的用户会自动进入“销售报价”，新建报价表单预选刚生成的成本决策；仅有成本岗位权限的用户留在成本页，并看到“已进入报价成本池，等待报价编制专员”。
5. 报价编制、报价审批/签发、信用审查、合同签署和订单创建继续由各自原子权限控制，报价、合同和订单始终引用固定版本及快照。

成本因子新增、修改和一键核算完成后，只刷新 `/api/v1/cost-matrices`；转入报价时只追加刷新成本决策。不得为了单个成本动作重新请求完整商业工作台。成本矩阵列表也不得返回页面未使用的完整因子核算轨迹；明细证据由后续业务命令按固定决策编号读取。
