# 2026-09-05 产品级审计与优化

## 结论与边界

项目已有从商机、技术规格、成本、报价到合同订单、采购生产、质量交付和回款的业务骨架。主要短板不是再加一层卡片，而是大量数据的加载方式、局部操作一致性、岗位交接可见性和可验证的运维边界。本轮实施可独立验收的修复，同时保留中期架构路线；不能把一次回归通过等同于所有岗位、客户网络和业务量均已达到生产 SLA。

## 本轮落地

1. **登录负载**：删除登录后对每个销售订单请求 `/360` 的 N+1 阶段。登录加载订单摘要；点击单个订单时读取合同、财务、履约和风险证据。正在处理的同订单请求合并，失败明确重试，再展开重新读取。100 个订单的回归场景中，此类首屏请求从 100 次降为 0 次；这不是公网总加载时间的百分比承诺。
2. **成本操作稳定性**：只有最后发出的成本查询可以更新结果、总数和查询条件；并发筛选合并，过时失败不干扰新结果。失败分页不推进页码，按钮可恢复重试；刷新搜索结果保留输入焦点和光标。采购来源因子不再把未使用的手工价零值当成实际采购成本显示，明确提示“核算时取有效采购价 / 以核算快照为准”。
3. **成本分页正确性**：同一 PostgreSQL 查询快照分别聚合总数及当前页，超出末页时保留真实总数，不再显示“总共零个模型”。仍限定租户范围；列表不返回完整因子轨迹。
4. **可访问性与移动端**：成本详情补齐 tablist、标签/面板关联、方向键、Home/End 和单一 Tab 焦点。业务台账按 Enter 时不再截获内部按钮的键盘事件；主动展开的订单证据不会被“重点字段”模式隐藏。800px 以下模型/因子/核算记录改为带字段名的双列行式布局，价格、来源和编辑不必向右拖动才能找到；操作按钮至少 44px 高。通用台账默认仅展开搜索/状态/数量，高级范围、导出与批量操作收进可展开区域；已有范围筛选会自动展开提示。纯空状态不生成工具栏、选择框或虚假的一条记录。
5. **审计边界**：成本详情只有拥有公司级 `audit:read` 的账号获得审计日志；普通成本岗位只获得业务因子和核算记录。默认拒绝日志，后端不查询/返回，前端不显示管理员日志页签。原有审计事件仍正常保存，没有删减追溯记录。
6. **空间及镜像**：API 仅安装生产依赖；Docker 上下文排除发布备份、测试报告及本地输出。三个项目容器各设置 `10m × 3` 日志轮转；不触碰同机其他项目，不执行全局 prune，不删除业务审计或附件。原有“发布全部检查成功后只保留最新恢复对、清理本项目未使用镜像”策略保留。
7. **质量门禁及文档**：依赖扫描恢复 fail-closed，服务不可达不再伪装为安全通过。修正 README 与生产部署文档的旧主机/业务范围描述。
