# 登录首屏按需加载与故障恢复

## 本轮编排及边界

承接上一轮产品审计暴露的跨公网静态文件下载慢问题。本轮按“同步门禁 → 登录/业务拆分 → 网络恢复与体积门禁 → 隔离数据库和浏览器回归 → 正式 CI/CD → 公网验收”执行。

起点：隔离工作树、`origin/main`、生产 `/version` 和 `.release-sha` 为 `1e80f2ed05185c137fbcb33ae72a505c4b327320`，三个 ERP 容器健康。唯一正式入口 `https://erp.kingturf.cn`；不调整 DNS、付费分发服务、市场价格、业务数据或迁移恢复点。

## 交付内容

1. **可先操作的登录界面**：`main.ts` 只加载 `entry.ts` 与登录样式；业务 JS 和 CSS 在会话验证后动态下载。HTML 自带中文加载提示和无脚本提示，弱网下不是一片空白。账号/密码增加显式无障碍名称，标志图低优先级下载且异步解码。
2. **明确阶段和恢复入口**：区分账号验证、会话验证、业务文件下载、业务数据读取与工作台构建。业务文件下载超过 45 秒进入可恢复界面；支持重试、显式刷新以获取新部署的文件、返回登录。下载失败不清除会话、不自动刷新循环、不重复提交业务命令。模块迟到只完成下载，不自行挂载旧工作台。
3. **完整请求超时**：共享 `http.ts` 把 15 秒超时覆盖到正文读取完成，保留关联 ID、幂等键、HTTP 状态与调用方取消语义，并清理外部取消监听器。以前响应头到达后即清除计时器，正文卡住可能无限等待。只有明确 401 清除会话；503 或资源错误保留会话。
4. **架构边界与防回退**：共享 DOM/状态反馈、会话类型、HTTP 请求从业务入口分离；每次挂载新会话清空在线文档读取缓存，原有权限判断不变。构建检查静态依赖图，登录 JS gzip ≤ 8,000 字节、CSS gzip ≤ 4,000 字节，业务工作台必须是动态入口。检查进入 `web build`，因此本地 CI、GitHub CI、生产 Docker 构建均执行，无需改工作流。

## 体积对比

| 指标（gzip，构建结果） | 上轮         | 本轮                           |
| ---------------------- | ------------ | ------------------------------ |
| 登录必需 JS            | 约 113.53 KB | 3.72 KB                        |
| 登录必需 CSS           | 约 17.87 KB  | 1.88 KB                        |
| 登录必需 JS + CSS      | 约 131.40 KB | 5.60 KB，减少约 95.7%          |
| 登录后业务 JS / CSS    | 包含在首屏中 | 约 111.55 / 17.08 KB，按需下载 |

这是**关键加载路径缩小**，不是业务总代码减少 95.7%。HTML、约 184 KB 的原始品牌 PNG、业务数据不计入上表。保留原始标志，不用生成图替换品牌。完整工作台仍需下载业务包；跨境网络延迟不会因拆包而消失。浏览器 gzip 数值与实际 Nginx 压缩字节数会略有差异。

动态模块的 CSS 随模块加载，由 Vite 在执行前准备好，避免业务页面无样式闪烁。依据：[Vite CSS code splitting](https://vite.dev/guide/features#css-code-splitting)。

## 验证与发布清单

- 专用本地 PostgreSQL：`kingturf_startup_test`，本机端口 55438；不使用现有 KingTurf/Phoenix/其他项目数据库。
- 单元测试：请求头、空响应、结构化错误、HTML 网关错误、成功/错误响应正文超时、取消监听清理；模块成功、45 秒超时、迟到与失败恢复。
- 浏览器在生产构建上验证：32 KB/s、150 ms 模拟网络登录可操作且不请求业务资源；会话确认后再下载；JS/CSS 下载失败保留登录并可显式刷新恢复；503/401 区分；既有登录、成本模型台账/编辑/核算/报价衔接、订单按需证据回归。
- 生产验收必须记录 PR、合并 SHA、CI/部署运行、`/health`、`/ready`、`/version`、`.release-sha`、三个容器与公共登录界面。浏览器模拟响应不等于真实受保护岗位 UAT；公网样本耗时不等于跨地区 p75 SLA。
- 部署仍通过 `.github/workflows/deploy-production.yml`；沿用成功后仅留最新部署恢复点及本项目未用镜像的策略，不执行全机 prune，不删除迁移恢复点。

本地执行结果：`pnpm ci:local` 全部通过，共 322 项测试（Web 101、API 139、数据库 61、领域 14、其他 7），严格依赖扫描无已知漏洞。生产构建浏览器回归 10/10 通过；同一生产 Nginx 镜像启动后再跑启动专项 5/5 通过，gzip 与哈希资源长缓存头有效。390px 登录截图人工检查通过，无横向溢出。发布和公网验收结果以对应 PR/工作流及交接报告为准。
