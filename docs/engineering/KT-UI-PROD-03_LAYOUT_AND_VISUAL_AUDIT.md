# KT-UI-PROD-03 页面布局与视觉审计

日期：2026-08-26

## 结论

整改前的业务能力已经完整，但视觉组织仍偏向“每条数据一个卡片、每个模块一个大卡片”。这种方式适合演示少量样例，不适合企业系统长期积累大量客户、订单、应收、工单和审批记录。生产级界面应区分四种内容：指标用摘要卡、流程用阶段看板、业务对象用紧凑列表或表格、配置模块用分区面板。

## 生产页面审计

| 页面           |        整改前结构 | 主要问题                               | 目标模式                     |
| -------------- | ----------------: | -------------------------------------- | ---------------------------- |

| 销售工作台     | 27 个卡片、无表格 | 多业务域同时卡片化，扫描路径长         | 摘要 + 分域任务队列          |
| 运营工作台     | 29 个卡片、无表格 | 生产、质量、计划记录缺少行式比较       | 摘要 + 单列业务台账          |

| 计划与生产     | 20 个卡片、无表格 | 业务量增长后多列卡片不可比较           | 计划看板 + 工单台账          |

| 系统管理与治理 | 15 个卡片、无表格 | 两列配置卡导致表格宽度和按钮位置漂移   | 单列治理模块 + 内嵌表格      |

## 本轮统一标准

1. 所有业务路由使用同一内容轨道、左右留白和最大宽度，不再由子模块自行决定页面宽度。
2. 页面只保留一个一级标题；治理页面内部标题降为二级标题。
3. KPI、风险数量和阶段汇总允许使用卡片；客户、报价、合同、应收、工单、发运和审计记录改为单列台账视觉。
4. 台账记录取消大圆角、渐变和悬浮阴影，以分隔线、状态和主操作建立层级。
5. 商机阶段、采购分栏等具有明确业务泳道含义的区域保留看板布局，不机械改成表格。
6. 桌面、平板和移动端保持同一信息顺序；移动端只改变列数和操作换行，不隐藏关键业务状态。

## 后续产品化方向

- 数据达到稳定规模后，将高频台账升级为语义化数据表格，补齐列配置、固定表头、分页、保存视图、导出和批量操作。
- 为销售、财务、生产、质量和物流分别建立默认岗位视图，避免综合管理员页面成为普通岗位的日常入口。
- 建立状态颜色、金额对齐、时间格式、空状态和危险操作的设计令牌与视觉回归基线。
- 卡片不作为默认容器；只有指标、独立决策、异常摘要和有明确边界的流程节点才使用卡片。
