# KingTurf V1.0 产品差距分析

基线 `b1ef7a9`。代码已形成多数业务模块；差距集中于跨域数量与金额守恒、真实岗位闭环和运行责任。证据定位见 [能力矩阵](business-capability-matrix.md)、[整改清单](debt-remediation.md)。

| 差距                                              | 分类与影响                                         | 推荐处置与优先级                                                         |
| ------------------------------------------------- | -------------------------------------------------- | ------------------------------------------------------------------------ |
| 多次部分收货被状态触发器拒绝                      | C；采购单可首收/结清，不能稳定处理三次以上分批来料 | 范围内P1，明确合法同状态证据，独立修复PROC001                            |
| 窄数据范围风险评价与投诉/驾驶舱锚点SQL错误        | C；真实岗位可用性受损，未证权限扩大                | 范围内P1，先兼容修复，再另裁SEC006/007强语义                             |
| BOM产出数量与展开公式不一致                       | C候选；原料计划与计划成本可能按批量放大            | P1候选，非1产出/多层/损耗及替代料独立对账                                |
| 发运物流记录缺原子出库与累计量联系                | C/E候选；批卷库存、重复发运和订单余量缺闭环        | P1候选，确定允许拆分的层级，先设计原子数量约束                           |
| 生产/需求来源只存类型、UUID或自由文本             | C/E候选；形式关联不能说明授权订单行与生产量        | P1候选，以真实订单行、批准额外需求和退补货语义设计                       |
| 制造成本使用Number                                | C候选，违反金额精确计算目标，实际边界影响待对账    | P1/P2依金额范围；复用现有定点或PG numeric，不换全栈                      |
| 实际制造成本按冻结政策计价；订单全成本/利润未完整 | E；报价毛利可能被误解为已实现利润                  | 纳入利润试运行则P1；先确认材料计价/费用分摊/汇率税费，分开展示估算与实际 |
| 请求响应丢失后通用表单重试取新key                 | C候选；持久化成功与UI失败组合可能重复业务记录      | P1候选，先逐接口响应丢失复现，不能直接全局自动重试                       |
| 列表文本匹配金额/日期，混合字段和币种             | B/C显示子能力；筛选和经营判断可能误导              | P2；使用具名字段、币种、日期口径，服务端筛选                             |
| 工作台用DOM条数/中文关键词推待办                  | B/D；缺责任人、到期与下一动作语义                  | P2；岗位任务读模型，复用审批/领域状态，非另造任务孤岛                    |
| 全量游标加载后前端分页                            | B/D；大数据量耗时和浏览器内存影响待测              | P2；确定业务量后按端点分批服务端分页/筛选                                |
| 草坪规格、单位换算与定额未完成真实业务签署        | E待核；误用M/M2/KG、草高Dtex与单耗影响全链         | 先访谈与真实样本，再小范围版本化约束，不硬编码未经批准的常数             |
| 联合恢复、离机备份、告警和值班缺当前实证          | E准入证据；故障后可恢复程度未证                    | Go前P1；只在获批隔离副本演练，RPO/RTO/负载由负责人确认                   |
| 全岗位UAT和两轮当前版本核心浏览器欠缺             | E准入证据；已部署不代表业务可试运行                | Go前P1；按范围冻结场景，不改正确断言或提高超时凑绿                       |

## 保留的工程成果

保留现有不透明会话与Cookie安全上下文、default-deny和SQL DataScope、数据库租户约束、不可变版本图、应收/收款/核销台账、事务outbox、幂等指纹、结构/Service门禁、真实PG和覆盖率规则、正式SHA发布保护。保留前端已完成的拆分、按路由加载及HTML清洗，避免重复治理已验成果。

## 范围约束

V1.0 聚焦获客到回款与授权制造交付链；是否将实际订单利润、费用、佣金支付与售后闭环纳入首轮范围由负责人签署。暂缓高级APS、IoT、完整法定财税、复杂报关、通用集成平台、AI自动批准与无需求的绩效平台。F是建议延后范围，不能据此删除已有数据或功能。
