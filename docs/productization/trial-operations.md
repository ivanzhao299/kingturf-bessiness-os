# KingTurf V1.0 受控试运行和维护方案草案

本方案仅在 [准入报告](release-readiness.md) 十二条件全部满足、负责人明确批准后执行。当前未启动试运行，未设置自动监控任务，也未获生产写入授权。

## 范围和责任

负责人签署组织、岗位、产品族、币种、业务流程、单量上限、操作时间、观察窗口和停止条件；未批准域维持既有权限。业务负责人对业务规则/差异和人工验收负责，发布负责人对版本/窗口/兼容负责，运维负责人对备份/告警/恢复响应负责；具体姓名、联系渠道、替补和权限待填写，不由代理虚构。

每批开通采用最小权限，真实用户确认培训和操作说明；不得临时共享管理员账户、弱化审批或绕过数据范围。异常工单必须关联单据、correlation、角色与版本；不在公共日志粘贴收款、客户、附件或认证秘密。

## 日常运行和指标

| 周期或触发             | 内容                                                             | 责任与输出                                       |
| ---------------------- | ---------------------------------------------------------------- | ------------------------------------------------ |
| 每个业务日/批准频率    | 订单/库存/回款/成本差异、待办积压、超期审批、失败同步            | 业务财务与仓库核账，差异不能静默置零             |
| 连续技术观测           | 存活/就绪/版本、API错误/延迟、PG连接/锁、磁盘/附件增长、备份成功 | 运维告警和值班；阈值按批准容量目标               |
| 每次发布               | 精确SHA、兼容预检、恢复材料、正式工作流、探针与变更说明          | 发布负责人；失败保全恢复材料，不自动反复重试发布 |
| 批准周期               | 独立副本恢复、附件哈希与引用、配置恢复、回滚启动/会话兼容        | 运维与独立复核；演练不直接改生产                 |
| 每次漏洞/权限/业务缺陷 | 分级、隔离影响、固定证据、授权修复、回归/对账                    | 主控登记，不让实施者自检替代审查                 |

不预设负载、响应时间、备份频率、保留期限或RPO/RTO数值；根据现有硬件、业务峰值、可接受损失和责任资源批准。保留现有恢复点，未经单独授权不清理数据库、附件、备份或共享镜像。

## 停止和恢复

发现跨组织泄露、金额/库存持续失配、非法过账、重复发运、关键审批失效、核心岗位无法工作或恢复材料不可用时，先记录和升级；负责人决定暂停相关新业务入口/回退窗口。代理不因问题自行停服。保留现状快照、日志和恢复点，避免重复点击或手工SQL补账。应用回退、配置回退、数据补偿、数据恢复分别评估和授权。

生产数据库不可直接为测试重置；所有证伪在隔离副本。已确认错误通过批准的业务补偿/更正记录处理，保持不可变历史。故障后核对实际runtime、marker、schema、附件和外部凭证，不能仅信工作流结论。

## 迭代和结束

问题分为阻断修复、普通缺陷、体验改善和范围外需求；每项关联KT-V1任务与TD/ADR，独立提交，风险适配测试，最终提交完整CI。例行架构整理不得吞没真实业务交付。观察窗口结束以真实岗位使用、对账差异闭环、稳定性和负责人签署决定扩大范围、继续观察或停止；日期到达不自动转正式运营。
