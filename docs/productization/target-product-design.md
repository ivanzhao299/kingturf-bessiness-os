# KingTurf V1.0 目标产品设计草案

以一笔有授权来源的订单贯穿技术、成本、供应、生产、质量、交付和经营收款；每个岗位只需处理本岗位有权限的待办，能知道状态、拒绝原因、责任人和下一步。设计基于 `b1ef7a9`，实施与业务口径待总体批准。

## 岗位工作面

| 岗位      | 进入后的首要队列                            | 核心动作和退出证据                           |
| --------- | ------------------------------------------- | -------------------------------------------- |
| 销售/外贸 | 客户跟进、待补CTR、报价状态、合同与回款承诺 | 需求完整、批准报价、精确合同订单、交期与余额 |
| 技术/工艺 | 待澄清需求、待发布方案/BOM/工艺、变更影响   | 可制造规格、版本固定、替代料/损耗说明        |
| 成本/审批 | 待审核成本和超政策报价、差异与缺来源成本    | 输入来源、公式/精度、规则版本、独立审批      |
| 计划/采购 | 已释放订单需求、缺料和MRP建议、待收货PO     | 可解释净需求、批准转单、多批收货、未交余量   |
| 车间      | 本岗位已释放工单、领退料和工序报工          | 数量/工时守恒、批卷可追溯、异常停工可解释    |
| 质检/仓库 | 待检/隔离/放行、待收/出库批卷               | 检验与处置证据、实际库存、库位与盘点差异     |
| 物流/履约 | 已满足放行条件的批卷、待装运和POD           | 出库与发运数量对应、物流里程碑、签收证据     |
| 财务/催收 | 应收、未核销收款、逾期、信用与佣金          | 经营台账可对账、银行证据固定、核销可重放     |
| 管理/售后 | 交付、现金、风险、利润差异与投诉超期        | 指标定义、截止时间、来源可下钻、责任明确     |

不允许浏览器prompt、手工SQL或临时脚本成为日常操作。已有原生表单保留，统一列表/详情/上游下游/审批历史/附件/操作记录。写入流程区分草稿保存、提交、确认、审批、撤回和补偿；失败可恢复且保持原业务意图身份。不可执行动作显示具体原因和下一处理者，后端仍最终授权。

## 单据和数量模型

保持稳定业务对象ID和不可变版本，明确客户→商机→CTR→方案→成本决策→报价→合同/信用→订单的精确引用。生产链补齐订单行→需求→MRP建议→工单→批卷→库存移动→发运行→POD的业务身份及数量来源。多对多关联必须有分配量、单位、累计余额和反向查询，禁止仅用字符串说明关系。

发运可分批/拼单与否、放行后可发次数和超发公差待裁定。推荐放行行固定批次/可发数量，实际dispatch在单事务内锁定可用库存与剩余额度、写出库和发运行、审计/outbox；重复原意返回原结果，新意图不得超累计量。退货、重发、换货通过补偿记录处理，不改历史发运。

规格按产品版本定义单位和有效范围。BOM明确产出基数、原料基准单位、每批定额、损耗及替代率，工艺固定作业顺序与报工口径。实测卷长/幅宽/面积/重量和质量结果属于批卷事实；报价估算不能静默覆盖实际值。

## 金额和成本口径

| 层次         | 数据来源与用途                                          | 禁止混淆                                     |
| ------------ | ------------------------------------------------------- | -------------------------------------------- |
| 标准成本     | 经批准BOM/工艺、标准单价与损耗                          | 不直接作实际库存法定计价                     |
| 报价估算     | 固定技术方案/成本规则/价格和汇率快照                    | 不显示为订单已实现利润                       |
| 实际制造成本 | 实际领退料、工时/机时、批准分摊及材料计价               | 当前冻结政策单价法须与真实财务口径核对       |
| 订单全成本   | 制造、物流、佣金、折让、售后、费用、财务/坏账等批准归集 | 未归集/暂估单列，不能把缺项当0后声称最终利润 |

保持金额十进制字符串与定点/PG numeric，明确交易币种、本位币、汇率来源/生效日、每步舍入与公差。跨币种核销、税费、佣金和费用分摊、关单后追补成本需要负责人/财务签署，不能由技术推断。只在四层和独立基准一致后确认“实际订单利润”。

## 外部系统权威来源和最小集成

| 数据                                     | 推荐权威来源                                    | KingTurf职责                                   |
| ---------------------------------------- | ----------------------------------------------- | ---------------------------------------------- |
| 业务订单、技术版本、工单、批卷、经营审批 | KingTurf                                        | 创建、状态、授权、审计和履约关联               |
| 法定会计凭证、税务/正式成本账            | 已确认的专业财务系统                            | 保存外部凭证ID/状态/对账差异，不假装总账       |
| 经营应收和收款分配                       | KingTurf经营台账；银行入账真实性以银行/财务确认 | 固定凭证来源，避免双系统重复收款               |
| 运单、报关、海关/税务记录                | 承运商/报关/专业系统                            | 保存外部标识、校验状态和附件；业务发运记录独立 |

先确定实际软件和流程再开发接口。最小同步使用公司+系统+对象类型+稳定ID+版本作为业务身份；每字段只指定一个主写方。按已提交领域事件/outbox向外发送批准单据，对方凭证状态回传；唯一键、canonical hash和重放身份防重复。失败使用有上限的退避重试和人工队列，认证/语义冲突不得无限重试；冲突保留双方版本供授权人员裁定；按币种、期间、对象数、金额和状态核对。最小权限服务身份与无敏感payload审计，禁止手工改对账余额。现阶段不引入通用总线或双向任意字段覆盖。

## 必须由业务确认

首轮岗位/组织/产品/币种/流程范围与业务负责人；草坪规格和单位/损耗；BOM产出基数；销售需求、分批/超产/超发与质量例外边界；四层成本/汇率税费/佣金口径；现用财务与物流软件及权威数据；真实数据脱敏样本；负载、响应目标、RPO/RTO及值班责任。所有答案写入带版本的决策记录，未答项阻塞对应实施而不冻结独立研究。
