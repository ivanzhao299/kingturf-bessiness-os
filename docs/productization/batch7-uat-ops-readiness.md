# Batch7 多岗位验收与运维准入准备

基线：Batch6 最终 SHA `040a5208e9972215c2e464d2b416ab09a4f46d07`。本文件只定义隔离环境的执行矩阵和运维准入方法，不批准成本、金额、发运、BOM 或利润业务语义变更。

状态含义：

- `已验证`：已有自动化或隔离环境证据，可作为前置回归，不等于人工岗位签署。
- `待人工`：需要真实岗位按固定候选版本操作并签署。
- `BLOCKED_BY_BUSINESS_DECISION`：依赖 Batch7 五项规则批准，当前不得伪造通过。
- `NOT_IMPLEMENTED`：当前版本没有可供验收的完整功能。

## 一、隔离执行约束

每次验收固定候选 SHA、Node/pnpm 版本、应用配置、隔离 PostgreSQL 数据库和合成组织。身份使用最小权限的合成账号，禁止使用生产账号、生产数据或生产连接串。每个场景记录输入来源、对象 ID、请求时间、审计事件/outbox、数据库对账查询、失败回滚和测试人员。

所有成功场景必须有对应拒绝、越权、重复执行或撤回场景。自动化结果和真实岗位签署分开记录；管理员 P1 浏览器回归不计入岗位验收。

```text

independent_reviewer:
```

人工签署只有在正向、拒绝、越权、重复/撤回、独立对账和恢复证据齐全后才能标记通过。任何缺项保持 `NOT_COMPLETED`。

## 四、性能基线方法

当前没有负责人确认的正式并发用户数、P95/P99、吞吐量、RPO 或 RTO，因此本批只建立可复现测量方法，不虚构目标：

1. 记录隔离环境 CPU、内存、磁盘、PostgreSQL 版本、连接池配置和数据量快照。
2. 以真实岗位场景的合成数据规模定义小、中、大三档；每档记录 API 请求数、成功/拒绝数、P50/P95/P99、错误率、数据库锁等待和连接峰值。
3. 单独测量库存 7+7、订单重复提交、事件 outbox、附件读写和后台任务，不用顺序循环冒充并发。
4. 记录冷启动、稳态、故障恢复三个阶段；测试结束清理进程、连接、临时 schema 和附件。
5. 由负责人根据实际订单量和服务器规格批准正式目标，批准前结果标记 `BASELINE_ONLY`。

## 五、备份、恢复和回滚准入

隔离演练至少覆盖数据库、附件、配置和版本清单四类材料：

- 备份前记录 schema 版本、迁移 checksum、对象数量和 SHA256 清单。
- 恢复到全新隔离 PostgreSQL 和空附件目录，验证迁移状态、关键订单/库存/审计对象和附件权限。
- 使用 Batch6 Git bundle 恢复代码后，以精确候选 SHA 构建并运行健康检查；代码树、历史迁移和 Git notes 必须可核对。
- 模拟应用启动失败、迁移不兼容和附件缺失，确认保持旧版本、停止写入并产生告警；不得用删除约束或跳过迁移恢复。
- 记录恢复耗时、数据差异、人工步骤和失败清理。未获得业务方 RPO/RTO 目标前，状态为 `BASELINE_ONLY`。

## 六、监控和运维准入

准入前必须有可定位到候选 SHA 的日志和告警：认证失败/会话撤销、权限拒绝、数据库连接耗尽、事务回滚、库存负数保护、幂等冲突、outbox 重试、后台任务失败、备份失败和磁盘空间不足。日志必须脱敏，不记录 token、密码、完整连接串或个人数据。

运维责任至少明确：一线发现人、值班负责人、业务升级人、数据库负责人和发布回退负责人。每个告警应有触发证据、确认时限、处置步骤、回滚条件和关闭证据；没有真实演练的项目标记 `NOT_COMPLETED`。

## 七、当前准入结论

- 合成岗位自动化前置：部分“已验证”，以 Batch1—6 的固定 SHA 证据为准。
- 十岗位真实人员签署：`NOT_COMPLETED`。
- 成本舍入、成本修订、发运扣库、BOM 冻结、订单实际利润：`BLOCKED_BY_BUSINESS_DECISION`。
- 性能正式目标：`BASELINE_ONLY`，等待业务量和服务器规格确认。
- 备份恢复隔离演练：需按本文件执行，当前 `NOT_COMPLETED`。
- 监控、值班和故障响应：需责任人签署，当前 `NOT_COMPLETED`。
- 试运行：`NO_GO`。
