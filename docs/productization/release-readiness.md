## 发布前必须保持的顺序

精确候选SHA属于主线→完整CI→环境/迁移兼容只读预检→数据库附件配置恢复材料与已验恢复→正式workflow_dispatch批准→精确checkout/并发锁/宿主校验→正式发布→本机与公网health/ready/version→实际版本和marker核对→运行观察。生产迁移、配置、重启、部署、数据恢复与清理不因审批总体计划而自动获准。

当前workflows已有重要保护：validate/verify/deploy、固定控制面、输入40位SHA、主线历史复核、production concurrency、SSH pin、迁移manifest、数据库备份、必要公网探针与版本marker。保留这些机制。工作流没有证明外部生产environment配置有人工审批；本轮未查其管理权限。

建议另行授权main保护：必须PR和独立审查、强制现行CI、禁止force/delete、明确管理员绕过与应急审计；生产环境审批与发布负责人分离。先确认团队账号/套餐/应急路径，再更改权限，不能为方便绕过现行发布守卫。
