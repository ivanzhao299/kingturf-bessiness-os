# Batch 4 BOM冻结与订单实际利润定稿提案

**BOM_VERSION/ORDER_ACTUAL_PROFIT=DESIGN_ONLY。** 本文不改变已批准的BOM产出基数和MRP销售订单来源规则，不实施成本计价、工程变更或利润算法。承接Batch2/3，重点给新工单可追溯依据和可解释的经营指标，未访谈确认的企业规则仍待负责人裁定。

## V1 释放时冻结BOM

现工单有DRAFT/RELEASED/IN_PROGRESS/COMPLETED/CLOSED/CANCELLED，固定产品与路线版本、计划开始/截止日期，但不固定BOM（0041:1–12）。MRP按effective_at≤asOf选择逐层BOM（mrp-repositories.ts:207起），制造成本却按最新published_at选择（production-cost-repositories.ts:123–139）。因此同一工单执行/成本可能偏离原计划；不能以当前最新版冒充历史依据。

首选V1：DRAFT只保存可重算预览；正式RELEASED在同一工单事务中冻结逐层manifest和hash、物料需求明细及原MRP proposal/run引用。推荐首版effectiveAsOf=释放事务时间，knowledgeAsOf=同次释放事务时间，使用当时已发布且已生效的版本；计划日期口径是备选，由技术/计划负责人明确后才能实施。UTC时刻与公司业务时区分开，不能把本次执行器的Asia/Singapore当成企业工厂时区。

manifest至少：工单/释放修订、产品/路线版本、每层BOM版本/父路径/子项ID、output_quantity、组件用量、计量单位与换算版本、损耗、允许替代料及转换、选择的effective/knowledge时点、来源与批准证据。相同物料可出现在不同路径，不能仅按itemId去重丢失需求；循环、缺BOM或单位不一致必须明确拒绝。数量展开继续使用已批准“需求产量÷产出基数×子项用量×损耗系数”，不借pin改算法。

新发布或追溯生效的BOM不会改动已释放manifest；需要变更则新工程变更记录说明原因、技术/质量批准、库存/采购/已报工影响及新需求差异。未领料的释放单可在批准后追加新释放修订，保留旧快照；已有领料/报工时按未完成部分追加受控变更或拆分后续工单，不能直接替换整单pin。已耗物料和历史成本仍引用原执行依据。

MRP历史run/解释不改；释放采用不同版本或数量时保存与原需求的差异，新增计划/采购调整及审批，而不是静默回算原run。实际替代料是独立执行记录，绑定原BOM行、实际itemVersion、单位转换、批准人和实领/退数量；不能通过修改冻结BOM使已发生领料看起来原本合规。

生产领退、报工、质量、成品卷、成本run均引用确切releaseRevision/manifest。成本政策价格仍独立冻结，BOM pin不代表实际采购计价已确定；缺费率触发器须与选定manifest兼容（见成本方案），不删除约束。前端释放前展示差异/缺料/版本状态，释放后显示只读依据、替代批准和变更链，不让用户输入裸版本JSON。

历史旧工单未证pin标UNKNOWN_ORIGINAL_BOM；material_snapshot可证明当时数量/价格，不自动证明BOM版本。可批准追加ATTESTED重建映射并标证据来源，不回填为原始快照、不覆盖旧hash。新业务切换后的写入不允许fallback到“最新已发布”；旧只读和受控未完成单处置需兼容ADR、向前迁移及识别新pin的回退构建。

验收：DRAFT预览变更、释放并发一次性冻结、释放后新发布、晚发布但追溯生效、多层重复路径/循环、替代料与单位、释放修订对采购/领料竞争、已领料工程变更、历史未知、成本与执行同manifest、跨公司/撤权/幂等及晚失败全回滚。V1待定：effective时点选释放还是计划生产日、释放后变更角色/范围、旧未完成单的证据准入。

## P1/P2 实际利润权威来源

当前dashboard bookedRevenue是订单金额、grossMargin是报价毛利、cashCollected是核销金额、commissionAccrued来自佣金case（dashboard-repositories.ts:23–42）；order360聚合未含制造cost run（order-360-repositories.ts:82–98）。制造run的“实际”是实耗/实报工按冻结政策费率计价，不等于供应商发票或法定实际成本；trace明确FROZEN_POLICY_RATE。不得把这些估算/政策计价指标改名为完整实际利润。

| 来源          | 目前可用事实                       | 候选权威/不足与防重复要求                                                           |
| ------------- | ---------------------------------- | ----------------------------------------------------------------------------------- |
| 报价估算      | 确切quote revision及cost decision  | 单列估算毛利，不能直接代替实际                                                      |
| 标准/计划制造 | BOM、路线、价格/费率政策           | 固定V1 manifest和政策；与实际执行区分                                               |
| 实际制造      | 领退、报工、已批准run，按政策费率  | 明示VALUED_AT_POLICY_RATE；实际采购计价FIFO/移动平均/批次实价未批准，不能凭名称假定 |
| 经营收入      | 订单/发运/POD/应收各有不同业务事实 | P1选确认时点、税基、币种/汇率、退货/折让；法定收入/凭证由外部财务权威               |
| 回款          | 收款/核销及应收余额                | 是现金与债权事实，不直接当利润收入                                                  |
| 物流/报关     | 运单、附件、服务凭证               | 费用需批准费用单或外部财务回传；运单状态不代表有成本0                               |
| 佣金          | case与不可变ledger，支付/冲回证据  | P2选应计时点；不能把计提金额和PAID流水再次相加作为两笔成本                          |
| 质量/返工     | 检验、投诉、报废、返工执行         | 已计入材料实耗的损耗不重复加；额外索赔/返工工单费用另有来源和分摊                   |
| 其他费用      | 经批准订单费用或外部专业系统单据   | 唯一来源ID/版本、归属订单与分类，未知不伪造                                         |
| 未完成/应计   | 未结算采购/物流/佣金/退货费用      | 分列ESTIMATED/ACCRUED/ACTUAL/REVERSED及未归集标志，缺失不填0当完整成本              |

首选经营成本归集行保存tenant、sourceType/id/version、原单行、费用类别、订单行/共享工单分摊、原币/税基、汇率快照、计价方法、发生/确认/截止时点、状态、批准与反向关联。唯一源标识防同单重复同步；同来源多订单分摊总额等于权威金额，明确舍入余差归属，不能按重复读到的总额各归一次。

估计被实票替代时追加反向/替代关联，不覆盖历史；客户退回、晚到费用和汇率更正形成新利润快照版本。政策计价与真实采购计价在同一视图必须明确标识，未选实际材料计价方法前不得宣称ACTUAL_INVOICE_COST。法定总账/税务不在本平台重复建设。

候选界面分列：报价估算毛利、政策计价制造差异、已归集实际费用、应计/估计费用、未归集警示及经营利润快照。仅当所有必要来源已覆盖且负责人完成截止检查时才标COMPLETE；未知项下只展示已知费用合计及暂估结果，不能显示“实际全成本/最终利润”。经营关闭与法定关账分开命名。

P1待定：经营收入时点、税基、汇率来源/方向与快照时点；P2待定：材料实际计价权威、佣金应计/冲回、物流/质量/其他费权威、共享工单分摊、晚到费用与重开责任。备选外部财务主导全部成本，系统只保经营来源与对账，不提前建复杂集成平台。接口只在真实双系统需求明确后实施，保证唯一ID、当前授权、幂等重试和独立对账。

验收：多币种/汇率日、部分交付/收款、未归集费用不得绿色完成、政策价≠采购价、两订单共享工单分摊、佣金支付不双计、已耗材料报废不重复、物流实票替代应计、发出/签收后退回、晚到费用新版本、撤权重放/跨公司/字段、外部重复回传与失败重试。需要财务独立基准和岗位签署，不以页面存在或单测数量放行。

## BOM选择歧义（V1补充，设计候选）

0036未约束同一产品只能有一个生效BOM；当前MRP的effective_at/version排序也不能唯一选择不同bom_id的同位版本。建议正式下达必须引用明确的BOM根版本：若当前有效候选唯一可预选；多个候选时拒绝自动下达，要求有权技术岗位显式选择并记录依据。按日期/版本/随机ID决定胜者不构成已批准业务优先级。多层子件同样先消除歧义再冻结清单，不能只固定根版本而让子BOM仍取latest。该候选需V1确认和真实PG双BOM同生效样本；现代码未改，历史工单不回填。
