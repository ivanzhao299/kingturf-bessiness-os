# KingTurf V1.0 真实业务验收方案

验收对象为负责人批准的岗位和业务范围、精确候选SHA及配置/数据库迁移状态。当前 `b1ef7a9` 未取得V1试运行人工签署。负责人提供脱敏真实订单/工艺/采购/库存/回款样本和独立基准；自动seed只能补充，不替代真实语义。

## 场景和独立基准

| 场景                         | 人工执行与成功证据                                        | 必需反例/并发与对账                                                          |
| ---------------------------- | --------------------------------------------------------- | ---------------------------------------------------------------------------- |
| 客户→商机→CTR→方案           | 销售/技术分别完成交接、版本和附件，重复录入可追查         | 外公司ID/无字段权限/失活角色拒绝；同时编辑冲突；固定版本不能漂移             |
| 成本→政策→报价审批签发       | 成本人员提供BOM/耗用/价格来源，审批人独立批准，报价可解释 | 低毛利/缺料/过期/自批拒绝；同意图重放；金额用独立定点/PG核算                 |
| 信用→合同→签署→订单          | 财务法务销售按分权形成精确引用及不可变证据                | 超信用/逾期/失效签署/错误引用拒绝；并发修订不叉版本                          |
| PO多次收货→库存              | 仓库对同单10分4+2+4，批次/库位和未交余量清楚              | 重复key、新key超收、并发收货、收货后outbox失败整体回滚；累计入库=收货        |
| 订单需求→MRP→生产            | 非1产出BOM、多层/损耗/替代料和冻结建议，可解释手算        | 假来源/外公司/无释放/超量需求、环BOM、重复run；原料量=按基准正确展开         |
| 工单→领退料→报工→卷→质量入库 | 操作者/质检/仓管按岗位完成；卷号、面积重量和批次追溯      | 缺料/负库存/重复卷号/超报/未检放行/越权处置、并发领料；实物与移动账一致      |
| 质量→放行→出库→发运→POD      | 合同信用回款质量法律门禁解释、装运批卷与订单累计量        | 同批多请求/新key重复发运/超累计/隔离批、未经例外或自批；退换货补偿可追溯     |
| 应收→银行回款→核销→催收      | 独立银行/财务证据与应收余额、未分配收款一致               | 重复入账、同key异payload、两人抢核销、跨币种/公司拒绝；分录/审计/outbox对账  |
| 实际成本→订单利润→关单→佣金  | 四层标清、费用来源、批准分摊、暂估和晚到项明确            | 大额/小额精度、换BOM/政策、未批成本关单、自批、费用晚到/退款；独立利润表一致 |
| 投诉→NCR→CAPA/催收法务       | 订单/批卷关联、独立验证关闭、完整证据与审计               | UUID别名、批量部分成功、重放、未完成证据/越权关闭拒绝                        |
| 附件/文档/审批/会话          | 上传下载/撤权/切换用户、打印/发送/版本、审批历史完整      | 路径穿越/非白名单类型/超限/跨公司/撤销会话，失败重试保原意图，外部送达另证   |
| 岗位工作台/移动与键盘        | 每岗从队列找到工作，知当前状态/下一动作/失败恢复          | 过滤字段/币种/日期与导出一致、分页不漏重、焦点/标签/错误反馈及适用WCAG项     |

金额对账按币种和精度分别计算，不用UI显示浮点作为独立基准。库存按物料版本/批次/库位/单位核“期初+入-出±调整=期末”，卷面积以实际宽长和批准公差核对；损耗、返工、报废和替代料必须有来源。成本基准由财务/工艺签署，不能复用同一业务实现重新算一遍就称独立。

## 执行与证据

冻结SHA、原测试/配置/fixture、迁移checksum和运行环境。隔离schema/身份/端口归属明确，任何有破坏性的验证只在获准临时资源。每场景记录执行人/复核人、角色组织、输入来源、预期/实际、对象ID、correlation、审计/事件和对账差异；敏感数据留受控位置，仓库只脱敏摘要/哈希。没有账号/环境不得skip后宣称通过。

开发者先自测，独立测试/安全人员复核关键事务和数据隔离，岗位负责人执行人工UAT。修复必须保留原失败证据并增加正确目标；改断言需业务行为批准，不能扩大超时、删除约束或绕权限。

当前版本完整 `ci:local` 与浏览器分层。Go前核心浏览器在同SHA、同配置/数据状态基准连续两完整轮通过；期间改源码、配置、spec、夹具或出现失败，就保留失败并在修复后重新开始双轮。网络失败算本轮失败，历史Harness替代证明不代替此条。认证/负例、文件/权限、回滚与跨组织不得被“只有成功路径”取代。

## 签署模板

每个场景填写：编号、批准范围、SHA、角色/组织、测试数据和独立基准版本、自动结果、人工结果、差异/缺陷ID、证据路径、执行人、独立复核人、岗位负责人、签署日期。空白或“待核”不当通过；阻断项关闭前不进入Go。

## 管理员和运维的独立场景

管理员场景：以经批准的真实岗位权限集，在隔离组织中创建授权、验证允许/拒绝和字段、撤销权限/角色或会话，再验证旧会话、已打开页面、附件和后台请求均不能继续使用已撤能力。输入为角色矩阵和组织样本；独立预期来自负责人批准矩阵，结果包含实际HTTP/页面反馈、审计事件和执行/复核人员签署。高级流程/主数据配置需同时核对是否要求原始JSON，以及普通岗位是否能绕过配置人员完成日常任务。

运维场景：在单独批准的副本环境监测健康/版本、模拟可控服务故障并验证告警送达和值班响应；从同一恢复点恢复数据库、附件和配置，按哈希/单据引用/金额库存快照独立对账，并验证候选版本、迁移状态和会话安全。输入为批准备份与恢复目标；记录实际步骤、恢复耗时、损失窗口、失败原因、恢复人员与独立复核。未经批准不向生产注入故障或恢复数据，空白验收表不能视为完成。
